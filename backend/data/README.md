# Data directory

This project keeps demo/synthetic data and real/external data in clearly
separate folders and **never mixes them silently**. Every processed record
carries a `source_type` of either `demo_synthetic` or `external_real` (see
[`../geospatial/schemas.py`](../geospatial/schemas.py)) so downstream
consumers (including any future ML training step) can always tell which
kind of data they're looking at.

```text
data/
├── raw/
│   ├── demo/       synthetic, hand-crafted data generated by
│   │               data/generate_dataset.py (fixed seed 42). Powers the
│   │               Phase 2 RandomForest model. NOT real-world data.
│   │
│   └── external/   real, user-supplied datasets (historical landslide
│                   inventories, rainfall records, DEM/vegetation exports).
│                   Empty by default — nothing is downloaded automatically.
│                   Not committed to git (see .gitignore) since real
│                   datasets may be large or license-restricted.
│
└── processed/      output of ml/preprocessing.py (numeric-encoded copy of
                     the demo dataset) and of
                     geospatial/pipeline.py::run_pipeline() (normalized,
                     validated external records + a metadata JSON
                     documenting provenance, validity counts, and
                     limitations). Regenerated, not hand-edited.
```

See [`raw/demo/README.md`](raw/demo/README.md) for the demo dataset's
specifics, and [`../docs/DATA_SOURCES.md`](../docs/DATA_SOURCES.md) for the
real-world data categories the geospatial pipeline is built to accept.
